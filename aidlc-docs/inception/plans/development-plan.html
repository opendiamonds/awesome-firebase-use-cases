1. 總覽 / Overview

Cloud-360 是 AI-native 多雲架構與維運平台，目前 SDD baseline 已寫入 9 大 pillar、26 條 user stories；尚未產製 application code。本計劃把這些 stories 依相依性切成 4 個 wave，從基礎設施（MCP/Skill registry、Agent Routing 骨架、Desktop shell）開始，逐步堆疊核心差異化功能、FinOps/Ops/Mobile 配套與擴充規範。
Cloud-360 is an AI-native multi-cloud architecture & operations platform. The SDD baseline currently captures 9 pillars and 26 user stories; no application code yet. This plan groups the stories into 4 waves by dependency, starting with foundational pieces (MCP/Skill registry, Agent Routing skeleton, Desktop shell) and progressively layering core differentiators, FinOps/Ops/Mobile supporting features, and extension governance.

5. 9 個 Pillar 細節 / Pillar Details

AArchitecture Design Wave 1

把自然語言需求轉成單雲／多雲架構藍圖，整合 Mermaid / PlantUML / draw.io，並支援 Active-Active / Active-Passive cross-cloud DR。

A1 · Natural Language to Architecture
  • 萃取 workload、HA、DR、scalability、region、security、compliance 需求
  • 產生 Mermaid / PlantUML / draw.io 輸出
  • 說明 assumption 與 trade-off
A2 · Well-Architected Review
  • 覆蓋 reliability / security / cost / operational excellence / performance 五支柱
  • 產生 severity、impact、remediation 建議
A3 · AI + draw.io Co-editing
  • 支援 .drawio / XML source format
  • AI 可加 / 刪 node、改 connection、標 data flow
  • 每次 AI 修改有 change summary 與 version history
  • 圖面可解析成 architecture graph 給其他 agent 共用

BCross-Cloud Component Selection Wave 1

依 workload profile 比較 AWS / GCP / Azure 同質託管服務，輸出 SLA、limits、lock-in、cost、ops complexity 與替代方案。

B1 · Service Comparison Matrix
  • 含 SLA、限制、相容性、成本風險、lock-in、維運複雜度
  • 覆蓋 compute、database、storage、network、Kubernetes、messaging、AI/ML
B2 · Workload-Based Recommendation
  • 使用 QPS、concurrency、data size、latency、region、compliance 限制
  • 提供 rationale、alternatives、known limitations

CCost Estimation & FinOps Wave 2

估算多雲 TCO、比較 Spot / Preemptible、計算跨雲 / 跨區 egress、提出 right-sizing 建議。

C1 · Monthly TCO Estimation
  • 估算 compute、database、cache、storage、network、CDN、egress、observability
  • 顯示 pricing assumption 與來源 timestamp
C2 · Spot / Preemptible Comparison
  • 覆蓋 AWS Spot、Azure Spot、GCP Spot / Preemptible
  • 含 savings estimate 與 interruption risk
C3 · Cross-Cloud Egress Analysis
  • 區分 intra-region、inter-region、internet egress、cross-cloud traffic
  • 標出昂貴 / 高風險 traffic path

DTerraform / OpenTofu IaC Wave 1

把確認後的架構轉為 Terraform / OpenTofu 模組草稿，支援 aws / google / azurerm provider，整合靜態安全掃描。

D1 · Modular IaC Generation
  • 產出 providers.tf、main.tf、variables.tf、outputs.tf 與 modules/
  • 支援 aws / google / azurerm provider
  • 禁止產生 plaintext secret
D2 · IaC Security Scan
  • 支援 tfsec、trivy、Checkov
  • 標出 public storage、過寬 ingress、缺加密、過寬 IAM/RBAC
  • 產出 remediation guidance

EOperations Optimization Wave 2

針對部署中或設計中的架構持續做健康檢查、效能、可用性與現代化建議。

E1 · Right-sizing Recommendation
  • 分析 CPU、memory、IOPS、network、storage
  • 估算改動後的成本影響
  • 調整 production 資源前需 approval
E2 · Architecture Modernization
  • 找出 legacy / 高維運成本 / 高雲費的服務
  • 建議 managed、serverless、container、event-driven 替代
  • 含 migration risk 與預期效益

FAI Multi-Cloud Operations Wave 0 Wave 2

透過 AI Chat 與 Agentic AI 管理多雲環境；高風險操作必經 human approval；所有操作寫 audit log。

F1 · AI Chat Cloud Query W0
  • 支援 account / project / subscription、region 選擇
  • 查 inventory、cost、metrics、logs、IAM/security findings
  • 含 data source 與 query time，遮罩 secrets
F2 · AI Chat Cloud Operation W0
  • Read-only action 經 policy 分類後可執行
  • Write / delete / deploy / permission change 需 human approval
  • 顯示 plan、impact、rollback、verification step
  • 記錄 audit log
F3 · Agentic AI Operations W2
  • 背景 agent 偵測 cost spike、安全風險、可用性缺口、效能瓶頸
  • 產出建議與 remediation plan
  • 無 explicit approval 時不執行高風險變更

GCloud Security Posture & Policy Advisory Wave 1 Wave 3

整合 AWS Config / Security Hub / GuardDuty / GCP SCC / Org Policy / Azure Policy / Defender 等資料源，提出可執行的治理建議。

G1 · Multi-Cloud Security Review W1
  • 檢查 IAM/RBAC、network exposure、storage access、encryption、audit logging、policy guardrails
  • 產出 severity、evidence、impact、remediation
G2 · Least-Privilege Analysis W1
  • 偵測 wildcard permissions、stale identities、unused permissions
  • 產出 least-privilege 建議
G3 · Policy-as-Code Recommendation W3
  • 支援 Terraform patch、OPA / Rego、Sentinel、Azure Policy、GCP Org Policy、AWS Config rule
  • 套用前需 approval

HWeb-Based Desktop & Mobile Experience Wave 0 Wave 2

Desktop Web 為完整工作台、Mobile Web 走 PWA 走伴隨介面；不做 native iOS / Android app。

H1 · Desktop Web Full Workspace W0
  • 支援 AI Chat、draw.io editor、IaC editor、FinOps / Security / Ops dashboard、agent trace、approval mgmt console
H2 · Mobile Web Ops Companion W2
  • Responsive web / PWA
  • 支援 AI Chat、alerts、approvals、health digest、findings、readonly diagram
  • 不需 native iOS / Android app
H3 · Mobile Web Approval W2
  • 顯示 plan、affected resources、risk、impact、rollback
  • 高風險 approval 需 MFA、Passkey 或 WebAuthn
  • 記錄 audit log，支援 timeout / escalation

IMCP & Skill Management Wave 0

整個治理層的命脈：MCP server registry、skill catalog、權限／風險模型、approval workflow、observability。

I1 · MCP Server Registry
  • 欄位：name、endpoint/transport、owner、environment、auth scope、enabled、version
  • 支援 health check（availability、schema 相容、latency、recent errors）
  • 禁存 secrets 於 config 或 log
I2 · Skill Catalog
  • 追蹤 skill name、domain、owner、version、description、required tools、risk level、change log
  • 支援 enable / disable / deprecate / rollback
  • 顯示 skill ↔ MCP tool ↔ SDK/CLI ↔ provider 的相依關係
I3 · Tool Permission & Risk Model
  • 分類：read-only、write、deploy、delete、permission-change、production-impacting
  • 高風險 tool 啟用或執行前需 approval
  • Agent Routing Layer 必須在選 tool 前看分類
I4 · MCP / Skill Approval Workflow
  • 新增高風險 tool、擴 auth scope、停用 critical tool 都要 review
  • 停用需 impact summary 與 rollback plan
  • 所有變更寫 audit log
I5 · Agent Tool Selection Observability
  • 顯示選用的 tool/skill、原因、input summary、permission level、approval status、execution result
  • 遮罩 secrets 與敏感 payload
  • 把 tool execution 連回原始 user request、agent trace、audit log

7. 已知風險與待解 / Risks & Open Questions

  • Wave 0 太重：MCP/Skill registry + Routing + Auth + Desktop shell 一次做太多。建議再細切成 W0a（registry + permission model + audit）／W0b（routing + chat shell）／W0c（desktop UI + auth）三個 sub-wave。
  • Architecture Graph 設計：A3 → C/D/E/G 都要吃 architecture graph。Schema 沒對齊就會回頭翻工。建議在 Wave 0 末或 Wave 1 起手就把 graph schema 先定下來（單獨 ADR）。
  • Pricing 來源時效性：C 系列要靠雲端 pricing API，價格資訊有時效；要規範 cache TTL、source timestamp、stale fallback。
  • 跨雲 IAM 概念對齊：G1/G2 要把 AWS IAM、GCP IAM、Azure RBAC 的差異攤平到統一 finding model，定義權限抽象層。
  • Approval Gate UX：F2、E1、H3 都會經 approval。Approval payload schema 統一才能在 Mobile Web 安全展開（H3 需 MFA / WebAuthn）。
  • Agentic AI 的副作用控制：F3 背景 agent 不可在沒 approval 時做高風險變更。建議用 Guardrail Agent + 預設 read-only。
  • Test 與 property-based 範圍：cost calculator、IaC generator、routing 是預設 enable 的 property-based extension。要在 wave 進入 construction 前先寫 property 草稿。

8. 下一步 / Next Steps

  1. Workflow Planning（推薦下一步）：以本計劃為輸入，跑 AIDLC workflow-planning.md，把每個 wave 拆成可執行的 unit / sprint。
  2. NFR 落地：把 SRS §7 的 NFR 各自寫成可驗收條件，作為 construction 階段的 hard constraint。
  3. Wave 0 細切：拆 W0a / W0b / W0c，避免「foundation 做太久卻沒可見成果」。
  4. Architecture Graph schema ADR：開 ADR-0007，定義 internal architecture graph 的 schema、序列化、版本策略。
  5. Reverse Engineering：repo 裡的 firebase_templates/、workflows/n8n/、tools/ 跑一次 AIDLC reverse-engineering 對齊新 SRS，標出可重用 vs 要丟。
  6. 啟動 Pillar I 的 inception → construction：Pillar I（MCP & Skill Mgmt）是其他 pillar 的前置。建議第一個跑完 AIDLC 全 inception 階段。
